# 交易/回测 Web 开发

用于交易、回测、行情研究、ETF、AI 选股、本地行情数据工作台。

## 先读

如果当前仓库有 `docs/development-sop.md`，先读它。那是项目里的详细偏好和踩坑记录。

## 固定流程

1. 先看现状：代码、接口、数据、测试、运行页面。
2. 串完整链路：数据源 -> 后端转换 -> API -> 前端状态 -> 展示/排序/筛选。
3. 修根因：不加假成功、静默 fallback、吞异常。
4. 小步改：不顺手大重构。
5. 真验证：相关测试 + build/compile + 浏览器页面。

## 数据规则

- “今天”“最近”“近 N 天”默认按交易语境处理，优先交易日。
- 最新数据日和自然日不一致时，页面要显示具体日期。
- 成交额、成交量、市值、换手率、收益率、波动率必须写清单位。
- 排序/筛选用原始数值，格式化只放在展示层。

## UI 规则

仅当本次任务涉及 UI 设计、实现或审查时，才读取 `/Users/a1234/.codex/skills/web-ui-design/SKILL.md`；非 UI 任务不要读取，避免浪费上下文。

本 skill 只保留交易/回测特有要求：

- 金融表格默认分页，表头点击排序。
- 参数说明优先用 `?` popup。
- 关键图表要能 hover/选中/拖动时间轴。
- 热力图滚动时标签不能错位。

## AI 规则

- 模型只解析意图，股票池筛选、排序、取前 N 必须走本地结构化数据。
- 不信任模型直接返回的 symbols。
- AI 结果要说明：匹配数量、筛选条件、日期窗口、使用的数据表/索引。

## 常见红线

- “选成交额最高 5 个”返回整个股票池。
- 按钮变灰但没有任务状态或错误提示。
- 指标名只有开发者懂。
- 单位必须读源码才知道。
- Docker 页面出现只能本机使用的文件夹选择或 TDX 操作。

## 验证

- 后端：相关 `pytest`。
- Python 包：`python -m compileall tdx_downloader`。
- 前端：`npm --prefix web run build`。
- UI：用浏览器打开对应页面确认关键交互。
